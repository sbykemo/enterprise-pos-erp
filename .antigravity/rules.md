**# Developer Team Workflow Rules**



**## 1. Planning First (Superpowers Brainstorming)**

**- NEVER start writing implementation code immediately.**

**- First step: Ask clarifying questions about requirements, scope, and edge cases.**

**- Second step: Write a clear Implementation Plan outlining which files will be modified and how.**

**- Third step: Wait for my explicit approval on the plan before touching any code.**



**## 2. Test-Driven Development (TDD)**

**- Write or update automated unit/integration tests before writing the actual code.**

**- Verify the test fails first, then implement the code to pass the test, then refactor.**



**## 3. Frontend \& UI Standards (Frontend Design)**

**- Do NOT use generic AI template styles (avoid repetitive purple/blue gradients, default Inter font everywhere, and boring 3-card layouts).**

**- Use distinct typography, intentional spacing, purposeful animations, and robust responsive design.**



**## 4. Code \& Security Review (Before Completion)**

**- Before telling me a task is finished:**

&#x20; **1. Check for common security vulnerabilities (SQL Injection, missing authorization, hardcoded secrets/API keys).**

&#x20; **2. Verify error handling and edge cases.**

&#x20; **3. Ensure no existing project features are broken.

## Session Context**

**- At the end of every major task, update MEMORY.md with any architectural decisions or major bug resolutions.**

**- At the start of any new session, read MEMORY.md first to understand the context.**
